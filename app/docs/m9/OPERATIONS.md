# Secure operations, recovery and incidents

## Backup and isolated restore

Freeze writes and stop workers before taking the inventory/object export/database dump to avoid inconsistent snapshots. Export the entire private bucket and relevant legacy objects without placing plaintext data in Git. Keep encryption key versions separately; prevent world-readable backup/export folders and restrict local operator access. `backend/scripts/recovery_m9.py backup backup.enc --objects exported-objects` checks every nondeleted document's object exists, captures erasure/document ledgers, runs pg_dump (credentials via environment), builds SHA-256 manifest and encrypts all content using M1_BACKUP_KEY. Refuses existing output, symlink/unsafe object paths or incomplete inventory. This bounded in-memory tool caps plaintext at 256 MiB; use a reviewed streaming method for larger deployments.

`recovery_m9.py stage backup.enc --target new-isolated-folder` authenticates, verifies exact manifest/members/digests, rejects absolute/traversal/drive paths, duplicates/links/oversized archives and existing target, then stages db dump/encrypted objects/ledger. It never runs pg_restore or uploads objects. Production restore is destructive and needs owner approval; use an isolated selected project first. pg_restore database.dump with restricted credentials, restore original encrypted object keys, verify table counts, storage completeness and encryption readability/key versions. Supabase Auth/Storage provider schemas and migrations require actual hosted rehearsal; PGlite restoration is local PostgreSQL evidence only.

Preserve the newest deletion ledger archive independently after each erasure, together with latest consent/revocation/business records. `replay_deletions_m9.py latest.enc` prints counts only; `--apply` is for an approved offline isolated restored target. It replays private workspace cutoff erasures and deletes tombstoned storage objects before marking metadata; it does NOT authorize applying an old database to production or automatically reconcile revoked consents. Update IDs/key mapping only with reviewed evidence. Replay is idempotent; keep traffic paused after failure. Verify post-backup withdrawals/revocations/final outcomes/session invalidation and purge deleted objects BEFORE permitting access. Record start/end/reconciliation and latest ledger references in a private recovery log. Destroy staged plaintext only within a verified absolute staging directory; keep encrypted evidence.

## Retention and queue failure

Run `operations_m9.py` with operator DATABASE_URL for counts only: overdue documents, dead letters, pending privacy reviews. Any overdue evidence is actionable; pause affected capture, keep provider/source switches off, run existing bounded retention_m1.py, retention_m3.py, background_m5.py --cleanup and chat_retention_m6.py paths, and service-only m9_metadata_cleanup. Check script names/flags in their help; do not guess destructive options. A worker crash must leave a lease for retry; never mark a failed storage deletion completed. If offline, show pending/unavailable and document cleanup delay.

Expired leases are reclaimed using token checks; stale workers cannot finish new leases. Five generic failures yield dead_letter; background has its own three-attempt unavailable policy. Inspect sanitized error codes/counts; do not log provider bodies, tokens, email/ID/documents or user rationale. Correct configuration/consent before an operator deliberately requeues the same idempotent reference under a new lease. No autonomous adverse message/hire or unlimited retry. Review oldest work age and bounded run duration privately. The test gate exercises generic SQL and provider lease replay; actual multi-process contention remains a hosted gate.

## Incident and rollback

Pause collection/external AI/senders; revoke relevant app/provider sessions, rotate affected keys through provider console and review encryption key migration privately. Preserve sanitized event IDs/timestamps/counts privately; never paste reports into telemetry/chat. Restore only after approval, isolation and newest deletion/revocation replay. Notify the assigned privacy/security owner; legal reviewer determines affected people, disclosure duties and deadlines [TBC-LEGAL]. No invented statutory deadline or automatic notification.

Traffic rollback uses a reviewed previous secured foundation bundle and compatible additive schema. Keep auth/RLS/private-storage boundaries, audit/scorecard/withdrawal/cancellation/tombstone history, deletion jobs and disabled official providers intact. Do not re-enable legacy public uploads or autonomous email. Never drop M1–M9 tables as a rollback shortcut. Restore encrypted backups only with explicit owner approval. Nonworking optional sources/models remain disabled; deterministic/manual/queued paths continue.
