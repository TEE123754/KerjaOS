# M3 — consent and human identity review

Local M3 is authorized; service keys and live checks remain deferred. Apply M1, M2 and CLI-generated M3 migrations only after the configured backup/restore rehearsal. No remote migration or real identity capture is performed here.

Default mode permits **synthetic test evidence only**. Real capture needs both IDENTITY_REAL_ENABLED=true on the server and real_capture_enabled=true in the private DB policy, after the separate legal/privacy/retention review. Configuring an API key does not activate this gate. Face/liveness and official eKYC stay off. Manual review does not claim NRD/official database verification.

Candidates see versioned EN/BM purpose/retention/access/reuse consent for a selected P2 application and employer. Each application receives its own consent record. They can choose MyKad, passport or an alternative human-review route with no upload. Missing/revoked/wrong-version consent blocks capture and review. Consent withdrawal cancels the case and expires evidence; assertion/sharing revocation is separate and preserves the profile.

Operator assigns qualified identity reviewers in kerja_private.identity_reviewers (qualified=true, active=true), plus the matching existing job assignment and employer HM/admin/reviewer membership. Cases select an eligible reviewer at creation. If none exists, the UI says awaiting assignment; the operator must assign the case explicitly once the reviewer is configured. Reviewers need AAL2 and cannot open another reviewer's raw evidence. This declaration is an operational qualification gate, not proof of legal accreditation.

PNG/JPEG/PDF upload: 3 MB, four megapixels for images, at most two unencrypted PDF pages. Images are decoded/re-encoded without source metadata, encrypted in memory and stored in the private bucket; PDFs remain opaque encrypted evidence. Plaintext, document number, DOB and OCR text are not persisted in the DB, logs, browser storage or external LLM calls. Structural/quality hints mean evidence assistance only. A low-detail image requests correction and cannot automatically pass. The human reviews readable evidence or personally completes the alternative route before recording verified_manual; synthetic cases become verified_mock. No provider stub can return verified_official.

Raw document retention is 24 hours from upload, shortened to one hour after verification and immediately due upon consent revocation. Access is denied as soon as consent is revoked. Run backend/scripts/retention_m3.py locally with server env configured at least hourly. It leases work, deletes the Storage object idempotently, then marks metadata deleted and records deletion evidence. Crashes leave a two-minute lease for retry. Fresh pending uploads are excluded until completed or stranded for one hour, preventing cleanup from racing an in-flight Storage write; completed revoked uploads are immediately eligible. Overdue raw objects globally block new identity capture until cleanup succeeds. Expired/stranded cases move to correction state. The worker is not automatically scheduled/deployed, so operator availability is a real outstanding service gate. M1 retention excludes identity documents to preserve this ledger.

Assertions contain only subject Auth UUID, reviewer/method/date/expiry and case linkage, never raw evidence or document numbers. A source assertion lasts up to 90 days. Sharing requires fresh target-application/employer consent and a receiving reviewer approval; only minimal assertions are shared. Root assertions can be reused across employers. Derived assertions cannot be reshared, preventing chained expiry/revocation bypass. Revoking the source assertion, a share, consent or reviewer membership blocks subsequent pipeline progression and interview entry. Raw documents are never shared with receiving employers.

OCR assistance is optional and local only: backend/scripts/identity_ocr_local.py reuses the legacy RapidOCR interface in an isolated operator environment. The hosted API never loads it. The CLI emits format/date flags only; absence of the optional model says not_configured. OCR/model-weight license/version, local hardware and EN/BM evaluation remain unverified, so the model is not installed or activated by M3. Face experiments remain deferred with separate consent/legal/license/evaluation/compute gates. Manual review works without OCR.

Demo: A consents to X, uploads a synthetic low-detail image, reviewer requests correction. A selects alternative review; qualified HM attests personally and creates a labelled mock assertion. A applies/consents to Y for another employer and shares that assertion; receiving reviewer approves the minimal assertion. Revoke the share and confirm Y cannot progress while X's source assertion/profile remain. Revoke source consent and confirm raw access is denied and cleanup is due. No automatic rejection occurs.

Rollback: stop new capture/review routes while preserving assertion/consent audit and continuing deletion. Never expose the bucket, revive revoked consent or restore deleted raw objects without deletion-ledger replay. Live Supabase Storage deletion/expiry, Auth/MFA/grants, proxy/hosting, worker scheduling and real-data legal approval remain pending. Local fixtures are not a completed deployed workflow. Tests run only at phase completion; gate fixes receive affected reruns.
