# M11 scoped descriptive analytics

React/Vite + FastAPI + Supabase Postgres; no new package, external analytics SDK, model, Redis, paid service or sender. Apply `20261005110000_m11_scoped_analytics.sql` after M1–M10 with backed-up isolated restore first. Local implementation does not apply remote migrations. `ANALYTICS_ENABLED=false` pauses report/export reads; observation capture and privacy portability remain intact.

## Cohort and metric definitions

Choose Analytics → Load analytics. No automatic dashboard fetch. Candidate scope is authenticated ownership; staff scope requires aal2, active HM/admin/recruiter membership and explicit job assignment via existing can_review. Optional job UUID must be assigned. Staff only sees internal assigned jobs, no candidate-private company/manual/discovery/resume data. SQL/RPC scopes the request using the user JWT; backend never uses a service key for reports/exports.

Default last 90 days inclusive; maximum 366 days, lower bound 1900. IANA timezone applies to internal creation timestamps and observed stage-entry timestamps; explicit manual date stays the supplied calendar date. No submitted timestamp is fabricated. Unknown dates (including discovery saved/applied self-reports) are excluded from dated totals, reported separately after origin/company/archive filtering. Range does not give unknown records an invented date. Manual considering records can have known dates; total is labelled cohort records, not proof of submission. Source means KerjaOS / Manual / discovery registry name; use source-name substring and origin filters plus source breakdown. Companies filter by case-insensitive substring. Archive applies only to manual records.

Totals/status/day/company/source groups count one origin+record ID, not events. Internal status/stage cards are current snapshots; closure, rejection, withdrawal are separate. Manual/discovery outcomes are self-reported and separate. Internal interviews count distinct cohort applications having a currently confirmed/completed M8 booking, not shortlisted P6 stages. Offers count canonical final_outcome offer/hired; acceptance does not imply hire. External offers count current offer/hired statuses, interviews current interview status. These outcome counts are current summaries, not lifetime conversion rates; each origin denominator is explicitly displayed. No candidate acceptance prediction, protected-trait inference or resume/evidence/note text in aggregates.

## Stage observations and truthful history

New private append-only observations capture application insertion and subsequent stage/status changes through a trigger. No backfill of invented stage-entry times. Current stage age uses latest captured stage entry; existing applications with no captured entry show unknown. Status changes/notes do not reset stage age. Re-entry resets current stage age but observed stage funnel counts each application once per stage within the cohort and selected observation date range. Funnel denominator is internal dated cohort, including applications without observations, so coverage can be incomplete. It is labelled observed stage entries, not lifetime conversion. Observations have no human reason/private text. They follow canonical application retention and operator-reviewed account disposition; private workspace erasure does not silently erase legally retained canonical business history. Candidate portability includes `analytics_observations` (100/page); private tables deny direct user access.

## Query bounds, export and privacy

At most 10,000 selected origin/company/archive records across dates before aggregation, and 20,000 observed stage entries within the dated cohort/range. Overflow raises an error, never silently returns truncated totals. Narrow company/origin/job filters for record budget and date range for observation budget. SQL materializes bounded intermediate rows; max 366 daily buckets per origin. Top 50 company groups shown with omitted-group count; outcomes/totals remain full bounded cohort. Per-function timeout intent is 5s, but hosted PostgREST/statement timeout and actual query/response/free-budget behavior require live measurement; no production SLA from WASM timing. Existing owner/job/event indexes plus new observation app/time index reused. No aggregate cache/persisted report or third-party telemetry.

CSV/JSON use identical scoped RPC filters. Export links preserve loaded filters even while form is edited; exporting refreshes current data, so concurrent changes can change counts. CSV uses quoting and neutralizes spreadsheet formulas after leading spaces/control characters. No row IDs, raw resume/evidence or private notes in analytics exports. Ordinary privacy portability may include owned stage application references. API/export remains no-store. EN/BM notices disclose processing and application retention; demo-only real-data switch remains enforced.
