# M10 tracker, companies and resume versions

Local synthetic baseline, React/Vite + FastAPI + Supabase. No new runtime package, paid sender, scraping expansion or external model. Apply 20261005100000_m10_tracker_workspace.sql after backed-up M1–M9 migrations and isolated restore approval; no remote migration/deployment was performed. TRACKER_ENABLED=true is the local default; false pauses new tracker API actions while retention/replay scripts remain usable.

## Owned tracker and company workspace

Sign in and choose Tracker → Load tracker. Internal applications, manual external records and M7 saved/source-linked trackers are unified as labelled origins. List is 50/page, with search/status/company/origin and known-applied-date range. Internal created dates are the available application date; discovery applied date stays unknown because a source click does not prove application. Date filters exclude unknown dates. External statuses are self-reported; internal statuses cannot be edited here. Current M7 saved records remain visible even if collection/source approval is off. Source-linked history is its current metadata snapshot, not a fabricated past event log; use Discover to edit/forget it.

Create a private company with optional normalized public domain and notes, then a manual external job title/URL/status/date/resume-version. Employer linkage uses only a published employer ID; it is not a role grant or verification claim. Candidate notes are private; HM/admin has no candidate-company/library permission merely through job assignment. No URLs/domains are fetched. HTTPS links reject credentials/local/private literal hosts; fragment/tracking params are removed and query sorting/trailing slash normalization enables duplicate checks. Canonical path case is preserved. Duplicate owner+URL raises conflict: refresh and explicitly edit/archive/forget the existing record after comparing it. No silent merge. Blank URLs are allowed for offline/unknown-source applications.

Company/manual edits require revision. Archive hides external records by default; Include archived restores their view. Forget requires the owned current revision; company forget is denied while manual jobs reference it. 100 companies and 200 manual records/account; UI loads company pages too. Latest 100 record events are shown, with manual snapshots preserving the recorded resume reference/status/notes at each edit. External applied dates can be unknown; known dates are 1900 through current Malaysia date. Manual status is not confirmed by an employer.

## Encrypted immutable library and snapshots

Upload a labelled unencrypted PDF (≤10 MiB, 1–20 pages). Each upload is a new immutable version, encrypted independently in the existing private bucket under owner/library/version.enc. No filename/raw file or private note enters browser persistence/logs/external models. At most 50 undeleted versions; lifetime is capped at 90 days using existing demo resume-retention baseline, not an indefinite storage promise or approved real-data policy. Preview links are signed for 60 seconds, owner/session-bound and recheck active session/current library expiry at every view; no direct browser Storage grant.

Create application resume copy explicitly choosing an eligible owned P0/P1 application and current application version. A new application-bound document receives newly encrypted bytes and immutable version provenance. Identity/credit consent is not reused. Copies start upload_pending, then a service-only completion rechecks stage/version/closed outcomes before quarantine. A race with application advancement/withdrawal expires the pending copy without replacing a snapshot. Retries using the same operation key reuse the pending document; an existing destination must match the original plaintext before completion. In the UI a new explicit copy click uses a new key; no existing application copy is overwritten.

The established human P1→P2 transition fixes its resume_snapshot_id to the latest eligible document. The links panel distinguishes a frozen submitted snapshot from a copy not yet fixed by screening. Future library uploads/retirement cannot change that document; stage/snapshot guards prevent replacing screened submissions. Application copy keys are independent of library keys. External record snapshots store user-reported resume version references; retiring an already-linked library version preserves that reference while preventing new selection/clone. Retire revokes access immediately, changes label to [removed] and schedules raw object cleanup. Existing application copies and provenance may remain for separate reviewed business retention; never promise full account erasure from library retirement.

## Privacy, cleanup, recovery and rollback

M9 privacy notice/export adds companies, manual_tracker, manual_history, resume_library and resume_links; ordinary exports omit object keys/hashes/raw files. Service-approved private-workspace erasure removes eligible external records/history/companies, clears retained company notes and expires/removes library labels, while application histories/copies remain. Existing/newer records after the replay cutoff are retained; referenced old companies may remain for those newer records, with old notes cleared. Account/legal retention is still manual. Raw expired library objects remain pending until the bounded worker succeeds; access is already revoked.

Run local backend/scripts/retention_m10.py with server-only configuration. Claim/complete uses a two-minute token lease; Storage deletion precedes metadata completion and M9 tombstone creation. Failures leave a lease for safe retry. One-hour stranded upload cleanup covers objects uploaded before a crash/failed mark-ready. No persistent hosted scheduler is installed. operations_m9 now counts expired library objects too. recovery_m9 inventories both application and library objects; replay_deletions_m9 matches latest tombstones against either table, removes objects first and restores deletion metadata. Older backups lacking M10 tables need the additive migration in the isolated restore target before this tooling. Latest ledger and post-backup consent/business records must be preserved as before.

Manual library retirement and company/record forget write service-only tracker tombstones. Preserve their newest sealed ledger alongside object/approved-workspace erasure ledgers. Replay removes forgotten manual rows before companies and expires retired library versions without deleting retained application copies. Conflicting company references stop replay for private review. Private-workspace replay covers its approved cutoff; ordinary post-backup edits/consent/business events still require reconciliation. No claim of complete account/legal deletion or hosted recovery. Preserve latest privacy/business change history for operator reconciliation. Metadata/tombstone/linked application retention needs the release policy review.
